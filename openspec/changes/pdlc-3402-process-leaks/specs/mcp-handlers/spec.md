# mcp-handlers spec delta

## ADDED Requirements

### Requirement: DecisionConsolidationDoesNotOutliveMcpServer

Консолидацию решений, которую порождает инструмент `record_decision` (`spawnConsolidateBackground`,
`src/core/services/mcp-handlers/decisions.ts:28-53`), сервер MCP SHALL гасить вместе с её потомками при своём закрытии
(`close`, в том числе по SIGTERM) и SHALL порождать без отделения (без `detached: true`), в группе процессов сервера
MCP, чтобы её достигал и сигнал группе. Пакет (PDLC-3407 п. 3) даёт эти два способа через «либо»; одного первого не
хватает для SIGTERM номеру сервера: по SIGTERM сервер выходит, детей не гася (обработчики
`src/cli/commands/mcp.ts:2132-2134`, `:2419-2421` только останавливают наблюдатель, без них — выход по умолчанию).
Консолидация и её потомки (CLI агента, который она вызывает) MUST NOT переживать закрытие сервера теми способами,
которые покрывают оба способа: SIGTERM номеру процесса сервера, по которому сервер выходит; сигнал группе, в которой
стоит сервер; гашение дерева сервера по номерам. Чужие процессы MUST NOT получать сигнала.

#### Scenario: Сервер MCP закрыт, пока консолидация работает

- **GIVEN** сервер `openlore mcp --http`, запущенный ядром Maestro, и рядом живущий чужой процесс-свидетель
- **WHEN** инструмент `record_decision` записал решение, консолидация ещё работает и ждёт медленный CLI агента, а сервер
  закрыт одним из способов ядра на pdlc-core `9f42086a`: SIGTERM номеру процесса, по которому сервер вышел (`close()`,
  `scripts/lib/ports/openlore-http.mjs:445`); SIGTERM группе прогона, в которой стоит сервер, и SIGKILL группе, только
  если корень группы не вышел за срок (`killTree`, `scripts/lib/proc-util.mjs:123-132`); SIGTERM каждому номеру дерева
  сервера и SIGKILL им, только если сервер не вышел за срок (`killSubtree`, `scripts/lib/proc-util.mjs:1645-1649`)
- **THEN** при каждом из этих способов процесс `openlore decisions --consolidate` и его потомки не живы
- **AND** процесс-свидетель жив
