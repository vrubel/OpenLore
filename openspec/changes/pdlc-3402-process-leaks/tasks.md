# Tasks — pdlc-3402-process-leaks (vrubel/openlore)

Порядок: сначала проверка, которая падает на коде тега `v2.1.3-ru20` и проходит на новом (процесс-утечка после
сценария жив, после правки мёртв; рядом живёт чужой процесс-свидетель, и он выживает), затем правка. Что не
воспроизводится на Linux-раннере (macOS, Windows), отмечается явно; живое подтверждение снимает владелец.

## 1. PDLC-3414 — консолидация решений (PDLC-3407 п. 3, F-OPS-021.R3)

- [ ] 1.1 Проверка: консолидация после `record_decision` ждёт подставной медленный CLI агента (команда со сном вместо
      CLI агента: без поставщика модели консолидация выходит сама, и проверка не покраснела бы), а сервер закрыт каждым
      из способов ядра, которые покрывает PDLC-3407 п. 3, так, как их исполняет ядро на `9f42086a`: SIGTERM номеру
      процесса, по которому сервер выходит; SIGTERM группе, в которой стоит сервер, и SIGKILL группе, только если её
      корень не вышел за срок; SIGTERM каждому номеру дерева и SIGKILL, только если сервер не вышел за срок. Подставной
      CLI агента перехватывает SIGTERM. На коде тега процесс консолидации или его потомок жив хотя бы при одном из них.
- [ ] 1.2 Правка: гашение консолидации и её потомков при закрытии сервера (`close`, в том числе по SIGTERM) и порождение
      без `detached: true` и `unref()`, в группе сервера MCP (`src/core/services/mcp-handlers/decisions.ts:28-53`), так
      что она и её потомки гибнут при каждом способе из 1.1. SIGKILL одному номеру сервера — предел механизма
      (proposal), проверкой 1.1 не судится.

## 2. PDLC-3414 — выход сервера MCP по закрытию stdin под ключом (F-OPS-021.R3)

- [ ] 2.1 Проверка режима `--http`: сервер с ключом `--exit-on-stdin-close` отвечает, пока труба stdin открыта, и
      выходит после её закрытия. На коде тега ключ не принят, и проверка красная.
- [ ] 2.2 Проверка режима stdio: сервер с ключом `--exit-on-stdin-close` отвечает клиенту и выходит после закрытия
      stdin. На коде тега ключ не принят, и проверка красная.
- [ ] 2.3 Ограда: сервер `openlore mcp --http` без ключа со stdin из `/dev/null` жив и отвечает — и на коде тега, и на
      новом.
- [ ] 2.4 Правка: ключ `--exit-on-stdin-close` команды `openlore mcp`, перечисленный в справке `openlore mcp --help` (по
      ней ядро узнаёт возможность бинаря); с ключом — выход по закрытию stdin в режимах stdio и `--http`, без ключа —
      прежнее поведение.

## 3. Тег и пин

- [ ] 3.1 Тег форка — только по отдельному слову владельца, записанному в PDLC-3414. Пин установщика
      (`scripts/forks.lst` pdlc-core) с пересъёмом зеркала промптов форка двигается тем же словом (задача 11.3
      локального изменения ядра). Передачу ключа ядро к пину не привязывает: оно передаёт ключ только бинарю, который
      его знает (задачи 11.1–11.2 ядра).
